## 1. Goal

Rebuild the frozen raw snapshot into a cross-project design system `<brand>` v<version>: three token tiers (primitive, semantic, component), components merged by function on three axes (variant, size, state), a lineage from every old value to its new token, and no source-project content in any example. Values stay original; elements and interaction mechanisms whose form is a late patch or a regression are replaced with common accessible patterns and recorded in the version log.

## 2. Scope and what is left out

In scope:

- All brand tokens, components and assets of the frozen snapshot.
- Merge thresholds written down before running (§ 10).
- Added states the source lacks only where the user decided which ones, marked `origin: added`.

Left out:

- Recoloring to raise contrast; new hues; new components.
- Migrating an existing package that is not in utility notation (P3); this package is delivered in Tailwind notation.
- Non-brand residue: listed and removed, not rebuilt.

## 7. Verification method

Hard rules (gate; `rationalize.py` writes its outputs and exits 1 when any of them fails):

- **H1 contrast does not regress**: every source pair recomputed with new tokens, its own opacity and the re-judged large-text class (new size and weight); a pair that passed must still pass; a pair with no new value fails unless excluded with a reason (`h1_excluded_pairs`).
- **H2 surfaces stay distinguishable**: opaque surfaces with different role drafts get different values.
- **H3 type order**: within a role lg > md > sm strictly; within one original variant, among the sizes in effect at each checked width, a smaller style stays strictly smaller.
- **H4 control box height**: deviation < 4px per control.
- **H5 no orphan primitive**: every primitive is referenced by a semantic or component token (scale families: by parts of kept variants).

Mechanical (all PASS):

- Generators idempotent: each run twice, output hashes equal; the package checker's staleness check passes.
- Cross-tier references only as allowed (composite semantic values may reference semantic colors; component tokens may reference tokens of the same component).
- Added states: focus ring ≥ 3:1 against every surface that can hold a focusable element; inverse ring on dark surfaces.
- New IDs and asset names clear of the forbid list; neutrality scan 0 hits.
- Handbook/spec values ⊂ JSON; anchors identical in spec, preview and mapping.

Independent (V1): full diff of token values against lineage; sample back to the baseline as `references/verification.md` sets it (sample size, or all when fewer); recompute all contrast; visual check of group layout and alignment, not only single components, against the source or the frozen evidence this plan names.

Cold start (V2): fresh agent, skill folder only, one full page; compare with a source screenshot of the same page type, or with the frozen evidence this plan names (`references/verification.md`, Cold-start trial).

## 8. Human checkpoints

1. Plan → independent review → plan stop (SKILL.md, Gates, step 3). The plan lists the verifier and the cold-start trial as work for the user to authorize (role, write scope, evidence).
2. After the plan is confirmed, before construction: freeze the P1 deliverable and export `<run>/baseline/`. Commit and annotated tag only when the user asks (`orchestrator-factory` hard rule 6; `commit-message-suggestion` `## Committing on request`).
3. Rationalization result (DL1–DL2) → **user reviews merges, removals, open items** when the user asked to see them; otherwise continue and report.
4. Package → V1 + V2 → fix loop (mapping/tokens → specs ∥ preview → handbook → full check → re-verify).
5. Orchestrator swaps staging into place (rollback commands written in this plan first) → **user reviews and accepts**, or the rollback restores the previous version.
6. The accepted version is frozen at the start of P3, after the P3 plan is confirmed.
