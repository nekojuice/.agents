# 認知資源管理

這是 [cognitive-work-sharing](../SKILL.md) 的參考文件，供人類理解、也供 agent 在本 skill 被明確調用後引導。[English](resource-management.md) 提供相同指引。它不新增角色、必要關卡或執行權限。

## 1. 從會委派工作，到管理自己的認知資源

開始能讓 agent 推進實質工作後，人面前的問題可能從「怎麼讓它做事」，轉為「如何承接它帶回的結果」。產出速度上升，判斷、整合、理解與介入的需求也可能集中到操作者身上。人的注意力因此成為整個協作系統需要管理的資產。

在本框架作者的實戰觀察中，當瓶頸從產出工作轉向理解成果與作出判斷時，可能出現「專注力不足」或俗稱「腦力認知浩劫」的情況。這表示有需要重整的工作負荷，不能據此判定已有進步或達到某種熟練程度。無論操作者經驗如何，都應檢查工作與回報的安排。

核心學習是：**不只管理工作如何完成，也管理哪些工作值得進入自己的思考，以及何時、以什麼形式進入。**

## 2. 人的認知資源不是固定 token 計數器

注意力、工作記憶、判斷投入與恢復需要，是認知資源的不同面向，不能視為可互換、固定容量的數值。同一份文件在不同疲勞程度、熟悉程度與工作脈絡下，可能有很不同的理解成本。

規劃時應容許能力下降並非等比例：持續增加工作，可能引起脈絡混淆、反覆重讀或漏看重要條件，讓返工成本突然升高。這是需要預留餘裕的工作假設，不是本文件已驗證的通用疲勞曲線。Agent 不應從簡短對話診斷使用者的生理或心理狀態。

成本至少包括：建立與恢復脈絡、比較方案、判讀證據、在工作間切換、承擔未決事項，以及錯誤後的返工。不要只計算 agent 執行時間或文件長度。

## 3. 元決策：投入思考之前，先選擇思考的對象

一般決策問「選哪條路」；元決策還會問「這件事現在值得決定嗎、先查什麼、誰準備材料、查到哪裡就夠」。它比待辦排序多處理了投入深度與停止條件。

以下問題是可按需使用的判斷視角，不是每次都必須填完的表單。

| 視角 | 要判斷的事 | 可由 agent 準備的材料 |
| --- | --- | --- |
| 目標與時機 | 現在處理會推進什麼？不處理有何後果？ | 與當前目標、期限及既有決策的關係。 |
| 路徑與相依 | 哪個前提不成立會讓整條路白做？ | 粗略路徑、關鍵前提、依賴與可能返工點。 |
| 資訊價值 | 哪個未知的答案會改變選擇？ | 能區分方案的查證或最小實驗，而非全面蒐集。 |
| 認知需求 | 現在需要人做哪種判斷？是否已準備到可判斷？ | 已知事實、取捨、推薦與剩餘人類決定。 |
| 停止與介入 | 什麼結果足以行動？何時值得重新決定？ | 停止條件、可逆下一步、會改變結論的新證據。 |

粗略預想路徑的目的是找出可能改變方向的條件，不是提前寫出完整施工計畫。若各路徑都需要某個前提，優先釐清它；若差異不影響眼前可逆的一步，可以延後深入。

## 4. 排定順序，也安排判斷何時到來

重要性、急迫性、是否已具備判斷材料，以及當下適不適合判斷，是不同問題。高優先事項可能應先由 agent 補齊證據；另一件已備妥的小決定則可能先完成。不要因為某份回報最先到達，就把它當作最該占用注意力的事。

Agent 執行工作會產生人類的下游工作。委派之前可粗估：會回來多少需要理解的成果、是否會同時等待同一個人的判斷、哪些結論尚依賴未定前提。這不要求限制固定 session 數量；要管理的是回報與決策需求的到達方式。

能依既有授權繼續的工作，不必製造額外人閘。需要人決定時，保留真正的取捨，把已查明的事實與可自行處理的事項先處理。可以依同一決策脈絡合併回報，同時揭露確有時效的重要問題，避免為了安靜而隱藏它們。

## 5. 決定研究何時夠用

研究值得繼續的理由，是下一份證據有機會改變選擇、避免重大返工，或使原本無法接受的不確定性變得可承擔。把預期收益與人類判讀成本、調查成本、延誤及放棄其他工作的代價一起考慮。這是定性判斷，不需要假造精確分數。

開始調查前，可先約定：「要回答哪個分歧？什麼證據會讓我們改變方向？什麼情況先做可逆的一步？」如果剩下的研究只會豐富背景，不改變目前選擇，就可暫停。若後果重大且仍缺關鍵證據，應明示缺口；停止研究不代表可以直接核可。

元決策也消耗認知資源。對清楚、低後果且容易復原的工作，直接處理通常比另開規劃更合適；對相依多、前提不明或返工昂貴的工作，前置推演才較值得投入。

## 6. 已經過載時，先重整工作介面

使用者表示腦力耗盡、看不懂大量回報或無法決定時，agent 先利用現有脈絡減少眼前的認知需求，不要再交回一份「你要選哪種解法」的巨大清單。

- 保留當前目標、已確認決定、未決問題與可續接位置，沿用既有紀錄。
- 區分已定案、可查證、已授權處理、確需人決定的事項；減少重複裁決。
- 把回報整理成當下需要的結論、依據、推薦、後果與剩餘未知；完整證據仍可追查。
- 若問題是理解不足，準備具體例子、解說或驗證；縮短文字本身不保證減少理解成本。
- 若現在無法判斷，說明可延後什麼、延後有何代價、哪些授權內工作仍可推進。保留必要核可，不以疲勞推定同意。

休息或暫停是合理選項，但不應取代對重複提問、錯誤分工與回報堆積的修正。也不要把既有契約外的工作自動擴大成「替人省腦力」。

## 7. 開發情境示例

某項架構選擇有兩條路，agent 建議同時深入實作比較。操作者已經收到大量其他 review 結果。

先確認真正的分歧：若兩方案的選擇主要取決於現行引擎能否提供某個介面，先查證介面或做小型實驗，比兩邊全面實作更有資訊價值。Agent 可先整理其他 review 中已有規則能回答的 finding，把仍需人取捨的事項依脈絡整理；不要求人同時重新理解所有任務。

介面可行性回來後，再呈現它如何改變路徑、剩下哪個取捨需要人，以及可先走的可逆一步。若新證據不能區分方案，就說明還缺哪個關鍵條件，避免以反覆討論消耗注意力。

此例改變的是認知投入的順序與形式，不要求新增 agent 節點、強制重型流程，或開啟額外平行工作。

## 8. 判斷這份指引是否有用

檢查的是：是否減少本可避免的重新決策與脈絡重建；是否提早發現會推翻路徑的前提；人是否仍能理解重要取捨並介入；是否留下足以續接的紀錄。更少提問、更快核可或更多產出，單獨都不能證明改善。

## 9. 依據與主張界線

[Griffiths、Lieder 與 Goodman，2015](https://onlinelibrary.wiley.com/doi/10.1111/tops.12142) 提出資源理性分析，從認知資源限制理解思考策略；[Callaway 等人，2018](https://arxiv.org/abs/1711.06892) 研究如何選擇計算、分配投入與停止。前者提供理論視角，後者是計算模型研究；兩者都沒有驗證本 skill 或量出操作者的疲勞曲線。

生成式 AI 的後設認知需求與實務編排成本，見[研究與心得索引 R1、P1](evidence.md)。本文件的工作安排是依這些觀點與作者實戰形成的設計建議。這裡描述的瓶頸轉移屬實務觀察，不是上述研究證實的發展階段或診斷標準。
