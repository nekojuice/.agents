## 1. 摘要

`discuss-first` 是任務的開場動作。啟用後 agent 進入 orchestrator／主導討論角色：與使用者對齊需求、界定任務邊界、整理「已定」與「待議」，並鎖定「只討論、不改任何東西」的預設，直到使用者以明確指令解鎖。鎖涵蓋所有專案檔（原始碼、設定檔、進入點程式、專案文件）。它只管開場階段，除了一則交接提示，不談收斂後的流程。

運作順序：

1. 啟用即上鎖：只討論，不開 change、不實作。需要改專案檔時，說明改什麼與為何，再問：opsx 專案問是否開 propose，非 opsx 專案依 §6 詢問；等明確回覆。
2. 使用者口頭授權修改時不拒絕，只解鎖使用者指名的範圍，並記錄授權（已有 run 時寫入其使用者決策紀錄，否則在對話中重述）。
3. 討論中：使用者指定範圍或順序時分 phase，每個 phase 內一次問完；能自行唯讀查到答案的問題不提出；回覆只答所問，與主題無關的嚴重風險只以一行「Exception reminder」提出。
4. 每次回覆整理已定事項；當前 phase 以外仍有未決議題時另列待議清單，每項附候選方案與單一建議。
5. 使用者明顯繞圈或卡住時，才附加額外建議。
6. 偵測專案是否使用 opsx，只用來決定收斂時的交接提示。
7. 收斂時給一則交接提示：opsx 專案提示 `/opsx-propose`；否則詢問要輸出成 markdown 文件還是直接實作。
8. 全程探索限於唯讀；僅供探索的寫入（暫存檔、解析腳本、額外相依）先問；專案檔變更不在探索層處理，一律歸鎖管。

## 3. 其他

- **提及後期事項的自我指涉**：開頭段要求不在開場提及後期事項（連允許或禁止都不提），但本 skill 自己在開頭段與 §6 以列舉方式提到「產出可貼上的指令、寫筆記、commit、archive」來排除它們（E3、E18）。這是 skill 寫給 agent 的指示，不是 agent 對使用者的回覆，但字面上與「連提及都不要」的要求有張力。
- **「直接行動指示」解鎖的範圍不明**：E5 把「任何其他直接要求行動的指示」列為解鎖條件，E8 的口頭授權例外則規定「只解鎖使用者指名的範圍」。直接行動指示是否也只解鎖其所指範圍，或解除整個鎖，本文沒有明說。
