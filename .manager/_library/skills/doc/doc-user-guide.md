## 1. 摘要

doc-user-guide 規範應用程式 UI 的終端使用者操作手冊，讀者是使用軟體的人（承辦、主管、操作員），不是工程師。它在用詞與風格上擴充 doc-general-guide，衝突時以本 guide 為準，並加入 UI 手冊需要的結構與元件。只適用於應用程式自身畫面；讀者是工程師、以管理工具或伺服器環境做部署、設定、接手的文件改用 doc-tutorial-guide。

使用順序：

1. 由淺入深理解系統：既有文件 → openspec → 實際畫面 → 定義狀態、角色、驗證、錯誤訊息的原始碼；畫面標籤、代碼、錯誤訊息以真實 UI 與原始碼驗證（§1）。
2. 規劃結構：章＝可分離的系統、節＝主要功能；先以書本式目錄取得使用者確認，無法確認就停在目錄，不寫內文（§2）。
3. 每個功能節依固定元素順序撰寫：功能標題 → 操作條件 callout → 進入路徑 → 列舉／狀態表 → 步驟 → 疑難排解（§3–§8）。
4. 全文只寫畫面上看得到的文字，畫面路徑依與 doc-tutorial-guide 相同的寫法，平實、單一語言（§9），以 §10 檢查清單收尾。

## 3. 其他

- **父層章節存在性**：§0 Inherited 與 Overrides 表引用的 §1、§2.1–2.4、§2.5、§2.6、§2.7、§2.9–2.10、§2.13–§2.18、§3、§4、§5、§7 皆存在於 doc-general-guide 1.2，內容與引用描述相符。
- **擴充範圍的措辭**：description 與開頭寫「就用詞與風格擴充」，但 Inherited 表也繼承了 §1 驗證、§2.17–2.18 職責與既定決策等非用詞風格的規則。
- **畫面訊息的引號未規定**：§9 只規定按鈕名稱用「」、選單節點用『』；§6 範例中「」同時用於按鈕名稱（「儲存」）與畫面訊息（「儲存成功：<日期> <變更者>」），畫面訊息的引號寫法沒有規則。
