## 1. 摘要

doc-openapi-guide 規範從程式產生的 OpenAPI 文件：操作摘要與說明、參數與欄位說明、回應說明、範例、文件層級資訊，以及讓 Swagger UI、Scalar 等檢視器正確且易讀顯示的文件相關程式碼。適用任何語言與框架。讀者是串接 API 的人，目標是呼叫端不必問人就能完成串接。它擴充 doc-general-guide，衝突時以本 guide 為準。支援對外讀者（預設，嚴格控制邏輯曝光）與對內讀者（可較詳細），並尊重專案既有的錯誤處理設計。

工作流程（§8）：

1. 確認讀者、語言、是否先看草稿三項輸入（§0）。
2. 寫曝光分析（§2）。
3. 由程式列舉實際回應與錯誤訊息（§5）。
4. 實作前：修訂既有文件先寫前後對照審閱報告，使用者審閱前不改；新建文件若使用者要草稿，先擬整份文字。
5. 直接實作文件相關程式碼；§5 列為決策的行為變更等使用者決定。
6. 專案有測試時，以測試鎖定結果。
7. 新建文件：交付時列出所有改寫過措辭的錯誤訊息（前後對照），供使用者確認。
