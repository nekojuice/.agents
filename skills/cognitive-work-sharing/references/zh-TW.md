# 人類與 agent 之間的認知工作分配

供人類閱讀、也供 agent 理解的認知工作分配哲學指引，搭配認知資源管理參考文件。請以 `$cognitive-work-sharing` 或明確要求使用本 skill 來調用；agent 不得自動啟用。這不是整套框架的完整操作手冊。

人類可用它判斷哪些思考應保留、委派或要求說明；agent 可用它協助操作者形成可負擔的認知工作分配。

[英文主檔](../SKILL.md) 提供相同指引。需要說明研究依據、限制或論點性質時，再讀[研究與心得索引](evidence.md)。簡單引導不需要一次載入所有參考內容。

當注意力、疲勞、累積待決事項或前置準備成本成為瓶頸時，讀取[認知資源管理](resource-management.zh-TW.md)（[英文](resource-management.md)）。它處理比工作分配更早的問題：哪些工作值得投入認知資源。

## 1. 我們操作的是什麼

Agent 協作的工程系統包含人、agent、規則、工具、紀錄與產物。自然語言規則需要在具體情境中被解讀，才形成實際意義。人類與 agent 將規則轉成工作、檢查結果，再維護規則。

這一層的能力，是理解如何組織思考與行動。使用次數本身不能證明已具備這種理解；懂得哲學也不能直接證明有領域能力或已成功交付。「哲學與經驗誰最重要」不是已有實驗支持的固定排名。

同一層抽象可以組織程式、圖像、模型、動畫或引擎產出的媒體。各媒介仍需要自己的專業方法與證據。跨媒介遷移是源自作者實戰的工作主張，不是所引程式開發研究已證明的結果。

## 2. 先辨認負荷從哪裡來

使用 agent 後，部分工作可能從親自製作產物，移到說清意圖、維持上下文、判讀證據、處理歧義與修正工作。產出更多內容或啟動更多 session，不等於取得更多可接受的交付。

人被問題淹沒時，不要直接歸因為不夠聰明、不夠努力，或缺乏天生的抽象能力。先看交到他面前的是什麼：重複提問、缺少證據、過時脈絡、不必要的打斷、矛盾回報，或確實尚未解決的重要取捨。

高魔壓裝置的故事，是操作者輸出與承載需求的比喻；agent 在故事中對應裝置。它不是測量尺度，也不表示現實 agent 能力無限，更不能拿來替人分等級。

## 3. 決定權與前置思考可以分開

人閘保留人的決定權，不代表決定之前的調查、比較與檢查，全都必須由人親自完成。

把問題交還操作者前，先依現有脈絡辨認它屬於哪種工作：

| 工作性質 | 適合的處理方式 |
| --- | --- |
| 規則或已確認決策已有答案 | 依記錄處理；有重要影響時說明依據。 |
| 可以查證的事實 | 查閱授權範圍內的來源，或安排適當調查；揭露仍不確定之處。 |
| 需要理解方案後果 | 在任務權限內比較或測試，帶回證據與重要取捨。 |
| 已明確委派、且有界線的決策 | 在界線內決定，揭露有重要影響的假設。 |
| 尚未表達的人類意圖、新的價值取捨或必要核可 | 帶著後果與適當的證據提出待決事項；能推薦時說明推薦理由。 |

不要把每個未知都當成人類待決事項，也不要因某方案在技術上較好就推定已獲授權。人已表達過的偏好，應作為工作依據，不必反覆請他重新決定。

## 4. 可以讓 agent 處理 agent 產生的問題

Agent 交出難懂的報告、大量問題或陌生結果時，人可以再次委派其中的思考工作：回查來源、區分事實與提案、找出矛盾、測試主張、解釋機制，或整理成可供判斷的形式。

依工作選擇既有 agent、worker 或已授權的 Helper。新增 agent 或增加交接層並不自然帶來改善。交接時保留原始問題、相關限制、來源指標、證據與尚未解決的不確定性。

多個 agent 同意，不等於獨立證據。另一個 agent 也可能繼承相同假設或問題框架。能取得時，使用原始來源、可觀察的結果或有意義的測試。反覆審查已不再增加證據時，停止循環並指出還缺什麼。

## 5. 保留足以介入的理解

將決策與脈絡外顯保存，減少人必須同時記住的細節。沿用專案既有紀錄，不預設另建一套知識正本。

把部分思考勞動交出去，與失去判斷結果的能力，是兩回事。操作者不必重建每個實作細節，但需要具有與任務、責任及錯誤後果相稱的理解。

重要結果若成為黑箱，就協助建立理解。可以使用依原始內容整理的解說、有反例的示範、圖解，或可展示行為的解釋。Agent 的解釋本身也是待核對的主張，不能因為說得流暢就視為證明。

有用的檢查是：操作者能否說明預期結果、接受它的依據、重要的剩餘不確定性，以及如何介入？完成速度本身無法回答這些問題。

## 6. 在當下卡住的位置提供引導

使用者只想討論概念時，解釋相關原則，不啟動執行流程。使用者卡住時，找出眼前的障礙，提出與問題相稱的下一步。

- 先利用可取得的任務脈絡；只詢問會實際改變下一步的缺漏資訊。
- 在既有授權內先解決或準備能處理的工作，再提出剩餘決策。
- 說明為什麼現在需要決定、選項會改變什麼，以及推薦的證據依據。
- 提供足以判斷的脈絡，不把每個內部發現一次全部壓給人。
- 若材料仍難以判斷，協助解釋或測試，不只反覆換句話問同一題。

例如，review 產生許多 finding。請人逐列裁決前，先對照已定案意圖、排除有依據的誤報、歸類共同原因，再區分範圍內修正與真正待決事項。必要時保留完整 finding 與判斷紀錄；精簡呈現不能隱藏未解問題。

又如，操作者只要求獨立 review 別人交付的 merge request，就支持這次審查與結果判讀，不自行擴大為實作或完整專案管理流程。

## 7. 配合工作，遵守既有契約

理解整套系統，不等於每次都必須採最重的流程。Debug、獨立 review、實驗與大型交付可以有不同工作安排。依預期成果、後果、驗證需要及既有規則說明安排的理由。

這份 skill 提供引導，不新增指揮者、核可權或必經階段，也不授予修改、派工、聯絡他人、安裝工具或擴大範圍的權限。原有授權與專案規則持續適用。讀取它本身不代表啟用 Manager、Factory、Helper 或建立教學工作區。

## 8. 學會可以遷移的原則

要建立的是可運用的協作模型：什麼需要決定、什麼能查明答案、誰有權決定、哪些工作能委派，以及如何檢查結果。

用解釋與有依據的案例讓這些關係可見，不把增加使用次數、背熟指令或改用更少 skill 當成解決認知過載的充分方法。

這些原則是可修訂的工程指引。區分研究觀察、實務心得與本地假設。研究支持認知工作的分布會改變，但未證明本框架必然降低負荷、每位新手都因同一原因受困，或委派愈多愈好。
